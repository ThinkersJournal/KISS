# Design — the cell class: #263 ruled D, one schema event (`sk5` + `contract_version` 3)

**Status: design + spec PR, for the PM's gate.** Measured at KISS `origin/main` `43b17b0`, 2026-10-11.
Supersedes `docs/decision-263-op-family-mapping.md`, `docs/rfc-op-family-mapping.md` and the
#263 part of `docs/proposal-wire-change-520-477.md` (each carries a pointer to this file).
**Version numbers are the PM's to allocate; `sk5` and `contract_version` 3 below are what the
change requires, not a request for particular numbers.**

## 1. The ruling

CireSnave, 2026-10-11, relayed by the PM, verbatim: *"D and drop the 24 names entirely."* The PM's
task text on it: replace the 24-code family in the key by a structural class derived from declared
hints; **no** op→family mapping table and **no** informative 24-name label kept; the "most specific
wins" ruling is moot; op identity is in every lookup; bundle the obligated `dequant_form` slot, the
extent-1 axis token fix and the field rename into one schema bump.

## 2. What the change is

| Surface | Change |

| Classify per-operand sub-key | optional sixth component `dl`/`dc` = `dequant_form`, iff the operand carries a `quant` record (§6.3-0009a, §6.6-0007, §6.7-0004) — the obligated slot |

## 3. The derivation (§6.5-0015)

First rule that holds decides. Inputs: the canonically ordered operands (each input / output /
in-place), the iteration frame, and three **caller-declared facts of the invocation**: the M/N/K
roles, the index-operand slot, the reduced-axis set. No op name and no op family is an input.

1. M/N/K roles declared → `ctr`
2. index-operand slot declared → `ndx`
3. reduced-axis set non-empty → `rdc`
4. pointwise by shape and `1 ≤` input operands `≤ 3` → `ew<n>`
5. otherwise → `oth`

*Pointwise*: at every frame axis every operand's extent (its own, or 1 where it has none) is 1 or the
frame extent, and every written operand (output or in-place) has the frame extent at every axis and the
iteration rank.

Why no caller-declared "family" bit: any such bit is the #263 defect again — two correct callers
choosing differently derive different keys. The three declared facts are not categories; each is
already a fact KISS-Ops states about the op (§6.11-0012, §6.13-0009, §6.19).

## 4. The 24 → 7 accounting (what CireSnave should read)

**6 codes are derivable from the declared facts and keep their distinction:** `une`/`bin`/`ter`
(→ `ew1`/`ew2`/`ew3`, the input-operand count), `red` (→ `rdc`, the declared reduced set), `gem`
(→ `ctr`, the declared M/N/K roles), `idx` (→ `ndx`, the declared index slot).

**18 are not derivable. All 18 lose their key-level distinction; what survives differs.** *Op
identity is what separates every one of them from its new class-mates, which is why it is now in
every lookup (§6.6-0002).* The columns say where the new cell lands and what, if anything, besides
op identity still marks it.

| Old code | Lands in | Besides op identity, what survives |
|---|---|---|
| `gat` (gated activation, split-in-halves) | `oth` (output is half the frame) | nothing. **`silu`/`gelu`/`mish` are pointwise**, so they now share `ew1` with `relu` — the old most-specific-wins ruling had put them in `gat` |
| `scn` (scan) | `ew1` (same-shape) | the `(acc+mp)` field when the accumulator deviates; nothing else — **same cell as a unary activation** |
| `nrm` (normalization) | `ew3` for `layer_norm` (x, gamma, beta), `ew2` for a two-input norm, `ew1` bare | nothing — same-shape |
| `sft` (softmax) | `ew1` | nothing — same-shape; its reduce field was already `-` (§6.6-0017) |
| `cnv` (convolution) | `oth` (shape changes); `ctr` if a producer lowers it to a GEMM **and declares M/N/K** | nothing — see the residue in §5 |
| `pol` (pooling) | `oth` | nothing |
| `emb` (embedding) | `ndx` | nothing — it was already a gather; distinct from `idx` no more |
| `shp` (shape/layout) | `ew1` (strided copy) or `oth` (transpose) | nothing; **no KISS-Ops op ever reached it** (ruled intended on #263) |
| `srt` (sort) | `ew1` | nothing — same-shape |
| `qnt` (quantization helper) | `ew2`/`ew3` by input count (scale, zero-point are pointwise inputs) | `dequant_form` (`dl`/`dc`) on an operand that carries a `quant` record — **new at sk5**; nothing for the rest |
| `rnd` (random) | `oth` (no input) or `ew1` (seed input) | nothing; no KISS-Ops op |
| `los` (loss) | `rdc` if the caller declares the reduced set, else `oth` | the declared set when present; no KISS-Ops op |
| `seg` (segment ops) | `ndx` if the caller declares the segment-id slot as the index role, else `oth` | nothing; no KISS-Ops op |
| `img` (image) | `oth` | nothing; no KISS-Ops op |
| `fft` | `ew1` (same-shape) | the dtype field only for complex (`c64`/`c128`); no KISS-Ops op |
| `lin` (linalg) | `oth` (solve) or `ew1` | nothing; **already unreachable** (`matmul` went to `gem`) |
| `att` (attention) | **`ew3`** when q, k, v share a shape; `oth` otherwise | nothing — a fused attention over same-shape inputs derives `ew3` |
| `moe` | `oth`; `ctr` if declared | nothing; no KISS-Ops op |

**The ones that bite**, in order: `scn` / `nrm` / `sft` / `srt` (key-level, same-shape, nothing else in
the key told them from `une` — they were separated by the family code alone); `gat` (a real
pointwise activation now shares a cell with `relu`); `att` (derives `ew3`). **The ones that cost
nothing today** are those with no KISS-Ops op (`shp`, `lin`, `rnd`, `los`, `seg`, `img`, `fft`, `moe`):
they were unreachable from the op set and stay unreachable; only a fusing producer that used to emit
them loses the distinction.

This is the cost of D, and it is the design working as ruled: the class is a fact about the cell's
structure; the computation is the op identity's.

## 5. Hazards and residue (stated, not hidden)

- **Collision by construction.** Same-shape non-pointwise ops share a class with elementwise ops.
  Safe only because a kernel is admitted on (cell, op identity) and §6.6-0001 already makes the key
  necessary, not sufficient. A consumer that looks kernels up by key alone gets candidates, none
  established to compute its op (§6.6-0002 now says so in terms).
- **Hint presence is still the caller's.** A producer that omits M/N/K on a matmul derives `oth`
  (the shape test fails — a safe-failing key, asserted in `test_classify_cell_class_derivation`); a
  producer that *declares* M/N/K on a convolution derives `ctr`. That is the one remaining degree of
  freedom. It is no longer a 24-way judgement but a yes/no per declared fact, each tied to a fact the
  op states in KISS-Ops. The Contract consistency requirement (§6.3-0006) catches the **declared
  but unsupported** direction (a `ctr` cell naming an op with no M/N/K iteration space); it does not
  catch the **omitted** direction, and says so.
- **Four or more inputs derive `oth`.** Adding `ew4` would reassign cells (not additive,
  §6.5-0006). Judged not worth a class now.
- **Decline spellings are renamed.** `UnknownOpFamily` → `UnknownCellClass`, `ReduceNotGatedToRed`
  → `ReduceNotGatedToRdc`; new `RdcWithoutReduce`, `BadDequantForm`. The decline vector `unknown_op_family`
  is `unknown_cell_class`. These are in the published artifact; every deriver regenerates anyway.
- **`SOURCE_COMMIT` in the vectors artifact is still the hand-written `19c3ad7`** (the known defect
  recorded at its declaration, #218). Not touched here.

## 6. Follow-on: op identity in every lookup — Announce (a second schema axis; PM ruled B)

Classify §6.6-0002 and the new §6.5-0015 note state that a lookup MUST carry the op identity beside
the key. KISS-Announce does not: its identity is the pair `(structure_key, revision_hash)`
(§6.3-0001, §6.4-0001, §6.4-0011) and a contract query is **key-only**. That was already a hazard
(`relu` and `exp` share a key at `sk4`); a coarser key makes it routine. **It is not changed in this
PR.** What it needs, as its own PR and its own `list_version`:

| Where | Today | Needed |
|---|---|---|
| availability record (§6.3-0001/-0005) | `(structure_key, revision_hash)` | `(structure_key, op_identity, revision_hash)` — a length-delimited `op_identity` between the two; `list_version` 2 |
| contract-query request (§6.4-0001) | `CYRQ` key + optional revision | `CYRQ` gains `op_identity`; a request without one is a typed decline |
| response echo (§6.4-0011) | echoes `(key, revision)` | echoes `(key, op_identity, revision)` |
| hit/miss (§6.3-0006) | key + revision | key + op identity + revision |
| harness | `announce.rs`, `announce_vectors.json`, `synth_*` | regenerated; Synth tests that build records |

Parties: every Announce speaker — Baracuda (provider), Fuel (consumer), and whatever Synth targets.
**Open choice for CireSnave/PM:** whether it rides the same coordinated event (one regeneration for
the parties, a bigger PR) or follows it (two regenerations). Recommendation: **ride the event** if
the lanes can take it, since the parties regenerate their key derivation anyway.
