kind: corpus fix: the ndx positive vector's index operand is u32, not f32
---
`cell_class_ndx_index_role_declared` in `conformance/corpus/structure_key_vectors.json` spelled its index operand as `f32`, outside the legal index dtypes `{u32, i32, i64}` of KISS-OPS-6.11-0009 (reported by Fuel's sk8 deriver, fuel#683). The class `ndx` comes from the declared index role, so the token's class is unchanged; only the middle operand's dtype sub-key changes: `co/00/v4/d16/f/f32` to `co/00/v4/d16/f/u32`, and the vector note says so. Regenerated with `emit_structure_key_vectors` (diff is exactly that vector); the §6.5-0015 worked example in `spec/classify.md` carries the same token and is corrected with it. `u32` now appears in a positive vector, so the pinned "usable dtypes appearing anywhere" count in `conformance/tests/structure_key_vectors.rs` moves 12 to 13 (coverage improved, as the guard asks). `conformance/corpus/structure_key_derivation_vectors.json` already used `u32` for this case. Consumers that vendor the corpus (Fuel, Fireline, Baracuda) re-vendor; a deriver that hard-codes this token must change its expected string.
