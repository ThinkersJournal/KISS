kind: op_facts.json gains declares_reduce_axis (additive, draft-tracking)
---
`conformance/corpus/op_facts.json` gains three per-op fields so a consumer deciding the `rdc` cell class (KISS-Classify 6.3-0006) no longer reads a null `reduce_axes` as "no axis": `declares_reduce_axis` (the op fixes a reduce, scan or sort axis), `reduce_axis_source` (`opattrs` when the op's own schema holds `reduce_axes` or `norm_axes`, `inner_carrier` when KISS-OPS-6.19-0036 sends it to the inner carrier of its reference decomposition, null otherwise) and `reduce_axis_inner_carriers` (the `reduce`, `prefix_scan` or `sort_network` that decomposition reaches, transitively). `cumsum`, `cumprod` and `cummax` resolve to `prefix_scan`; `argmax` and `argmin` to `sort_network`; `avg_pool` and `max_pool` to `reduce`. `matmul` also reports `reduce` (its decomposition folds K), so a consumer that treats contraction as `ctr` ahead of `rdc` (6.5-0015 rule order) keeps its answer. The generator reads the 6.13 decomposition graph; `avg_pool`'s row names a bare op rather than a call, which the stock reader of `tools/kiss_ops.py` misses, so `tools/kiss_op_facts.py` adds that case. `reduce_axes` keeps its meaning (own OpAttrs field only). Existing fields and the file path are unchanged; consumers that vendor the file re-vendor. `tools/test_kiss_op_facts.py` pins the scan, argmax, pool and non-declaring cases.
