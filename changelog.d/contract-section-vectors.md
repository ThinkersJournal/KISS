kind: contract section vectors for FireLine (additive artifact keys, stricter section reader)
---
Additive to `conformance/corpus/contract_vectors.json`: a `section_vectors` key carries whole seven-section documents (header v4) in two sets, built by the library from the Appendix C blocks with one change each. Accept vectors (6): a strided `add` signature in the §6.11-0006 descriptor layout (extents, strides, `n`; the `launch_scalars` tail equals the signature tail), the five-field Dispatch (`invocation_domain`, `workgroup_sizing`, `count_to_grid`, `thread_mapping`, `addressing_rule`), `output_layouts` present, `human_annotation` present, `in_place = input:0` and `input:1` with non-empty `in_place_eligible_variants`. Decline vectors (50): the V11 stride descriptor declared `scalar`, a five-slot descriptor, Dispatch with a field missing, out of order, beside the sentinel, or with an unparseable, out-of-vocabulary or unsubscripted expression, `output_layouts` not last, `human_annotation` before `op_dag`, `in_place` = `false` / `input:01` / `input:` / a missing input, and for each of Identity, Semantics, Interface, Capabilities, Guarantees, Provenance one dropped field, unknown key, swapped keys, repeated key, non-UTF-8 byte and CR line. Each decline carries `section` and a stable kebab-case `expect` tag (`SectionDecline::wire_tag`, `DispatchDecline::wire_tag`, `SignatureDecline::wire_tag`), never `Debug`.

Reader changes the vectors needed: `parse_section_block` now declines a repeated key (`DuplicateField`), a non-UTF-8 block (`NotUtf8`, was `BadHeading`) and a line carrying CR (`MalformedLine`; it used `str::lines()`, which silently stripped the CR and accepted CRLF against §6.11-0001); new `parse_semantics_block` (§6.4-0001 `{semantics_kind, op_dag, human_annotation?}`), `parse_positional_signature` and `SignatureDecline` (a launch class 1/2 must be `rank`, 3/4 `scalar`), and `read_full_document` in `conformance/src/section_vectors.rs`. The golden document's bytes do not move; `coverage_note_496` item (i) now points at the new key instead of saying the five-field path is never exercised.

Open for the PM/CireSnave: the tag names and the `ptr_<dtype>` pointer `type_token` and `i32` `n` spellings are this lane's picks (told to FireLine), and §6.11-0006 pins no decline for a wrong `array_len_kind`, so `array-len-kind-mismatch` is a reading of §6.5-0004a, not a quoted rule. Tests: `conformance/tests/contract_section_vectors.rs`.
