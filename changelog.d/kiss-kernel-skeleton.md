Board 450 (CireSnave, 2026-11-16: "A...but only as long as the necessary references are kept in place so readers know when recommendations are available") created KISS-Kernel, the kernel-body sub-standard. This is the skeleton and the references; **no barrier, atomic, fence, collective or race rule is stated**, because the six choices that gate them are board 459 (`docs/kernel-body-eleven-choices.md` records all eleven).

Added: `spec/kernel.md` (front-matter, informative sections, a reserved section map, KISS-KERNEL-6.1-0001 and the freeze gate KISS-KERNEL-8-0001) and `spec/sidecar/kernel.json`; umbrella section 2.1 paragraph and two STRUCTURAL edge rows (Classify and Ops to Kernel), counts nine to ten; the KISS-Ops "Downstream edges" row and a new section 6.22 "Kernel-governed ops" table (`scatter`, `scatter_add`), with a `*Kernel-governed:*` pointer appended to KISS-OPS-6.11-0006, -0010 and -0024 (no clause's obligation changes); the tool lists (`kiss_trace`, `kiss_freeze_gate`, `kiss_scoped_cites`, `kiss_tables`, `kiss_uncited`, `kiss_bundle`); and `tools/kiss_kernel_refs.py` (a lint: a governed op with no pointer, a pointer with no table row, or a table row naming a section absent from kernel.md fails it) with `tools/test_kiss_kernel_refs.py` (six mutation tests), and `conformance/tests/kernel_refs.rs` (the same check, independently, Proven by mutation).

Bytes: `conformance/corpus/op_facts.json` gains one `kernel_rules` line per op (the sections that govern it; `[]` for the other 126) and a `fact_clauses` entry; `schema` stays `kiss-op-facts-v1` (additive; the Rust reader looks fields up by key). No digest, manifest, golden, wire or `structure_key` byte moves. Coverage floor: harness 564 to 565, proven 25 to 26. KISS-Conform's own text still says "eight other sub-standards"; its coverage set is not extended to KISS-Kernel until a rule section is published (KISS-KERNEL section 9).
